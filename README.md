# Blinkythm - 눈 깜빡임 리듬

웹캠으로 눈 깜빡임 빈도를 살피다가, 화면을 오래 보고 깜빡임이 줄어들면 짧은 리듬 게임을 제안하는 Windows용 프로그램입니다.
입력은 눈 깜빡임 하나뿐이며, 박자를 알려 주는 방식이 서로 다른 미니게임 세 가지(한 판 약 35초)와 세 게임을 잇는 메들리가 있습니다.

## 설치와 실행

**설치 파일로 쓰기**: Releases에서 `Blinkythm-*-win64.zip`을 받아 압축을 풀고 `Blinkythm.exe`를 실행합니다.

**소스로 실행**: Python 3.10~3.12 (Windows, 웹캠 필요)

    pip install -r requirements.txt
    python main.py

처음 실행하면 설정 마법사가 열립니다(카메라 확인, 타이밍 보정, 옵션). 마법사가 끝나면 트레이로 들어가 백그라운드에서 동작합니다.
`Blinkythm.bat`로 콘솔 창 없이 실행할 수 있습니다.

시험용 옵션
- `--sim`: 카메라 없이 실행. 게임/마법사에서 스페이스바가 눈 깜빡임을 대신합니다.
- `--demo`: 화면 사용 12초 만에 알림이 뜨도록 조건을 낮춥니다(설정은 저장되지 않습니다).
- `--background`: 창을 숨기고 시작합니다(자동 실행 등록 시 이 옵션이 쓰입니다).

## 미니게임

| 게임 | 방식 | 하는 일 | 길이 |
|---|---|---|---|
| 등대 신호 | 따라 하기 | 등대가 한 마디(4박) 동안 보낸 불빛 신호를 다음 마디에 같은 박자로 깜빡여 돌려준다. 6라운드. | 약 35초 |
| 올빼미 합창 | 이어 가기 | 첫째와 둘째 올빼미가 운 간격만큼 기다렸다가 세 번째로 깜빡인다. 간격은 1박, 0.5박, 1.5박, 2박. | 약 37초 |
| 깜빡 사진관 | 2박 뒤에 | 손님이 종을 치면 언제나 정확히 2박 뒤에 깜빡여 셔터를 누른다. 종이 겹쳐 울리거나 박 사이에 울리기도 한다. | 약 33초 |
| 메들리 | 모두 | 세 게임을 차례로 한다. 게임 사이에 3.5초 쉰다. | 약 2분 |

- 알림에서 "지금 하기"를 누르면 게임 선택 창이 열리고, 지난번에 한 게임의 다음 게임이 골라져 있습니다. Enter로 바로 시작합니다.
- 각 게임은 4박 세기로 시작합니다. 반주는 게임마다 다르고(92, 100, 112 BPM), 신호음은 반주와 함께 미리 한 버퍼로 합성해 재생하므로 화면이 버벅여도 박자가 흔들리지 않습니다.
- 화면 아래 가이드 막대는 8박 단위로 넘어갑니다. 윗줄은 들린 신호, 아랫줄은 내가 깜빡일 자리입니다. 깜빡일 자리는 그 자리를 알려 주는 신호가 나온 뒤에야 점선으로 나타납니다(설정에서 끌 수 있음).
- 결과 화면은 판정 개수, 정확도, 구간별(메들리는 게임별) 정확도, 타이밍 분포를 보여 주고 가장 좋았던 구간과 약했던 구간을 한 줄로 알려 줍니다. 게임별 최고 기록이 저장됩니다.

## 알림 조건

다음을 모두 만족할 때 화면 오른쪽 아래에 알림이 뜹니다. 값은 설정 탭에서 바꿉니다.

1. 얼굴이 계속 보인 시간(화면 사용 시간)이 기준(기본 20분) 이상
2. 최근 1분간 깜빡임이 분당 기준(기본 12회) 미만. 얼굴이 40초 이상 보이지 않았다면 판단하지 않습니다.
3. 전체 화면 게임/영상, 발표 모드가 아님 (Windows 알림 상태 API로 확인)
4. "다시 알림" 대기 시간이나 게임 후 중단 시간이 끝난 상태

얼굴이 90초 이상 사라지면 자리를 비운 것으로 보고 화면 사용 시간을 0으로 되돌립니다. 게임을 한 판 끝내도 0으로 돌아갑니다.
알림창은 키 입력을 가로채지 않도록 기본 버튼 없이 뜨고, 처음 1.2초 동안은 버튼이 눌리지 않습니다. 90초 동안 응답이 없으면 "다시 알림"으로 처리합니다.

## 판정 설계

입력 시각은 "눈을 감기 시작한 순간"입니다. 프레임 두 장 사이에서 눈 뜸 정도(EAR)가 임계값을 가로지른 시점을 선형 보간해 구하므로
30fps 카메라(프레임 간격 33ms)에서도 그보다 세밀하게 시각이 잡힙니다. 감기 시작이 두 프레임 연속 확인되면 곧바로 판정하고, 이벤트가 늦게 도착해도 시각은 원래 값을 쓰므로 판정에 영향이 없습니다.

| 등급 | 박자와의 차이 | 점수 |
|---|---|---|
| 완벽 | ±70ms 이내 | 100 |
| 좋음 | ±130ms 이내 | 75 |
| 아쉬움 | ±200ms 이내 | 40 |
| 놓침 | 그 밖 | 0 |

- 키보드 게임보다 창이 넓은 이유: 웹캠 프레임 간격과, 눈 감기를 박자에 맞추는 사람의 편차가 크기 때문입니다. 카메라가 30fps보다 느리면 창이 자동으로 더 넓어집니다.
- 장치 지연 보정: 웹캠·소리 출력의 지연은 장치마다 다릅니다. 마법사에서 메트로놈에 맞춰 8번 깜빡이면 박자 주기로 접은 오차의 중앙값을 구해 저장합니다. 편차가 크면 측정을 거부합니다.
- 박자와 무관한 평소 깜빡임은 감점하지 않습니다. 어떤 노트와도 ±200ms 안에서 맞지 않는 입력은 무시하고 결과 화면에만 횟수를 표시합니다.
- 한 번의 깜빡임은 가장 가까운 아직 판정되지 않은 노트 하나에만 대응합니다. 노트 사이 간격은 모든 게임에서 0.5초 이상으로 잡아, 한 깜빡임이 엉뚱한 노트에 붙지 않게 했습니다(시험으로 확인).
- 잘 맞히면 게임마다 정해진 소리(배의 종, 내 올빼미 울음, 셔터)가 나고, "아쉬움"이면 그 소리가 작게 둔탁한 소리와 함께 납니다.
- 놓침은 노트 시각 + 창 + 0.18초가 지나야 확정합니다(입력 이벤트가 늦게 도착할 수 있기 때문).
- 0.8초보다 길게 감은 것은 깜빡임 통계에서 제외합니다(졸음/휴식).
- 결과 화면에 박자 대비 분포를 보여 주고, 평균 오차가 한쪽으로 30ms 이상 치우치면 보정값 반영을 제안합니다.
- 등급: 정확도 85% 이상 "훌륭해요", 65% 이상 "좋아요", 40% 이상 "보통이에요", 그 밖은 "다시 도전해요".

## 개인정보

영상은 메모리에서 눈 랜드마크를 계산하는 데만 쓰이고 저장하거나 전송하지 않습니다. 네트워크 기능이 없습니다.

## 구성

    main.py                 진입점
    blinkythm/detector.py   EAR 시계열 -> 깜빡임 감지 (적응형 임계값, 보간)
    blinkythm/monitor.py    화면 사용 시간, 분당 깜빡임, 알림 조건
    blinkythm/stages.py     미니게임 세 가지의 채보(신호, 노트, 구간)와 설명
    blinkythm/rhythm.py     판정, 구간별 평가, 보정 계산
    blinkythm/audio.py      WAV 읽기, 한 판 음원 합성, 재생(pygame)
    blinkythm/tracker.py    웹캠/MediaPipe, 시험용 가짜 트래커
    blinkythm/ui_scenes.py  게임별 장면 그리기(PNG 스프라이트)
    blinkythm/ui_*.py       메인 창, 게임 창, 알림, 마법사
    blinkythm/winenv.py     작업 영역, 전체화면 감지, 시작프로그램 등록
    assets/sprites/*.png    픽셀 그림(원래 크기로 저장, 게임에서 4배 확대)
    assets/sounds/*.wav     효과음, 신호음, 반주 루프(44.1kHz 16비트 모노)
    tools/make_assets.py    위 PNG/WAV를 만드는 코드: python tools/make_assets.py
    tools/make_icon.py      exe 아이콘 생성
    tests/test_core.py      핵심 로직 시험: python tests/test_core.py

## 애셋

그림과 소리는 모두 이 프로그램을 위해 `tools/make_assets.py`로 만든 것입니다. 그림은 글자 지도로 그린 픽셀 그림이고,
소리는 사인파, 잡음, 감쇠 곡선을 조합해 합성했습니다. 난수 시드가 고정되어 있어 다시 실행하면 같은 파일이 나옵니다.
그림이나 소리를 바꾸려면 이 파일을 고친 뒤 다시 실행하고, 결과 파일을 함께 커밋합니다.

## 알려진 한계

- 이 개발 환경에는 웹캠이 없어, 감지 로직은 합성한 EAR 시계열(30fps/15fps, 장치 지연, 잡음)로, 화면과 흐름은 가상 디스플레이에서 키보드 입력으로 시험했습니다. 실제 웹캠에서의 감지 품질은 사용 환경에서 확인이 필요합니다.
- 안경 반사, 고개를 많이 숙이거나 돌린 자세, 어두운 조명에서는 EAR이 흔들려 감지율이 떨어질 수 있습니다. 눈 뜸 기준은 최근 30초의 평소 값에서 자동으로 맞춥니다.
- 소리 출력이 블루투스 이어폰이면 지연이 크고 불안정합니다. 마법사 편차 검사에서 걸러집니다.
- 개발 환경에 소리 장치가 없어 반주와 효과음은 파형 수치(길이, 최대 음량, 신호음 위치)로만 확인했습니다. 음량 균형은 실제 스피커에서 확인이 필요합니다.
